Overview
--------
Task P7.5 verifies and completes the accessible Disconnect confirmation dialog workflow and the Reconnect notification banners across the application:

1. Accessible Disconnect Confirmation Modal (#outlookDisconnectModal):
   - Defined in index.html with accessibility attributes: role="dialog", aria-modal="true", aria-labelledby="outlookDisconnectTitle", and aria-hidden="true" (when closed).
   - Dialog copy strictly satisfies SPEC.md §4.1:
     - Clear warning: "Are you sure you want to disconnect your Microsoft Outlook account?"
     - Exact honest revocation guidance: "This deletes Sloane's copy of your Outlook access and clears diary and email data from the dashboard; to fully remove Sloane's access from your Microsoft account, use https://myapps.microsoft.com (or the link Microsoft shows under your account's connected apps)."
     - Truthfulness constraint: explicitly avoids false claims that Microsoft has revoked external consent.
     - Token erasure guarantee: "Zero tokens will remain on the server. You can reconnect at any time."
   - Focusable controls:
     - Modal header close button (`.modal-close-btn` with `data-close-modal`)
     - External guidance link to `https://myapps.microsoft.com` (`rel="noopener noreferrer"`)
     - Cancel button (`#btnCancelOutlookDisconnect` with `data-close-modal`)
     - Confirm Disconnect button (`#btnConfirmOutlookDisconnect`)

2. ModalManager Accessibility & Ergonomics:
   - Traps focus strictly between first and last focusable elements (`button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])`) on `Tab` and `Shift+Tab`.
   - Global `keydown` event listener safely dismisses active modal upon `Escape` key press.
   - Click-outside handler closes modal when clicking backdrop (`.modal-overlay` or `.modal-backdrop`).
   - Locks background body scroll on open (`overflow = 'hidden'`) and restores when all modals close.
   - Saves `lastFocusedElement` on trigger open and automatically restores focus upon modal dismissal.

3. Disconnect Execution & Post-Revocation Notice:
   - `confirmDisconnect()` in `scripts/components/outlookSettings.js` disables `#btnConfirmOutlookDisconnect` during transit with a loading label (`Disconnecting...`) to prevent double-submits.
   - Invokes `POST /api/v1/integrations/outlook/disconnect` which deletes the vault record, clears in-memory caches, and returns honest revocation guidance with `zeroResidualTokens: true`.
   - Closes modal via `ModalManager.close('outlookDisconnectModal')`.
   - Renders post-disconnect revocation notice banner in Settings view directing user to `https://myapps.microsoft.com`.
   - Re-renders card in `not_connected` state and calls `window.app.refreshOutlookData()` to reset Command Centre diary and email panels to honest empty states.

4. Reconnect Banner (§4.1 & §4.4):
   - When Outlook connection status is `reconnect_required` (e.g. refresh token rejected, `invalid_grant`, or consent revoked):
     - Command Centre dynamically renders `#outlookReconnectBanner` with warning icon, explanation, direct action link (`/api/v1/integrations/outlook/connect`), and dismiss button.
     - Eyebrow dot turns red with `Private CEO Command Centre · Outlook Reconnect Required`.
     - Settings card displays `reconnect_required` status pill with Reconnect and Disconnect actions.
   - When status returns to `connected` or `not_connected`, `#outlookReconnectBanner` is hidden and dismissal flags are reset.

5. Security & Static Shell Hygiene:
   - `index.html` static shell contains 0 literal `@` symbols and 0 client entity leaks.
   - Server-side vault contains 0 residual tokens after disconnect.
